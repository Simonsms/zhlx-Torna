# Torna 控制台 UI 优化第一阶段 PRD

## Problem Statement

Torna 当前登录后控制台采用多套独立布局，主要交互仍是“左侧入口点击后替换单一内容区”。这套结构能够完成功能，但存在以下体验问题：

- 缺少统一的全局顶部导航，空间、项目、用户和管理上下文之间的层级不够清晰。
- 左侧导航、模块页签、文档目录和内容区同时竞争视觉注意力，信息层级弱。
- 内容区只能展示当前路由，用户在多个工作页面之间往返时缺少清晰的访问记录。
- 面包屑只覆盖部分层级，无法稳定表达“空间 / 项目 / 功能 / 当前资源”的上下文。
- 缺少统一的功能搜索和快捷导航入口，高频操作依赖逐层寻找菜单。
- 色彩、间距、边框、阴影和组件密度缺少统一规范，页面呈现更接近基础管理模板，而非开发者控制台。

项目仍使用 Node 12、Vue 2、Vue Router 3、Vuex 3、Element UI 2 和 Vue CLI 3。第一阶段必须在现有技术栈内完成，不通过框架升级解决视觉问题，也不得引入后端改动或改变既有业务逻辑。

## Solution

为登录后的 Torna 管理控制台建立统一的控制台外壳，并分阶段迁移现有布局。第一阶段提供：

- 全局顶部导航：品牌、上下文、功能搜索、快捷入口、帮助、消息和用户菜单。
- 左侧垂直主导航：保留现有路由和权限判断，统一入口位置、选中态和折叠行为。
- 右侧工作区：由面包屑、路由 Tab 条和业务内容组成，业务页面本身不重写。
- 路由访问 Tab：所有登录后工作页面均可打开或复用，首页固定不可关闭；不缓存组件实例。
- 功能导航搜索：搜索控制台功能与快捷命令，通过现有路由打开页面，不实现文档全文搜索。
- 导航型快捷入口：跳转到现有页面，不跨组件直接触发创建、导入或发布流程。
- 统一视觉规范：以紧凑、清晰、低干扰的开发者控制台风格统一色彩、间距、字号、边框、阴影和状态反馈。

第一阶段只调整控制台外壳、导航组件、路由元数据、前端状态和样式。空间、项目、文档、成员、常量、发布等业务组件继续沿用现有接口、权限和生命周期。

## User Stories

1. 作为已登录用户，我希望在所有管理页面看到一致的顶部导航，以便确认自己仍处于同一个控制台中。
2. 作为已登录用户，我希望清楚看到当前空间和项目上下文，以便避免在错误的项目中操作。
3. 作为已登录用户，我希望通过左侧主导航进入现有功能，以便沿用熟悉的业务路径。
4. 作为已登录用户，我希望当前导航项具有明确但不过度突出的选中态，以便快速定位当前位置。
5. 作为已登录用户，我希望内容区具有稳定的标题区、Tab 区和正文区层级，以便扫描复杂页面。
6. 作为已登录用户，我希望首页作为固定 Tab 保留，以便随时回到控制台入口。
7. 作为已登录用户，我希望访问业务页面时自动新增或复用对应 Tab，以便在多个任务间切换。
8. 作为已登录用户，我希望同一路由资源不会重复创建多个 Tab，以便避免工作区混乱。
9. 作为已登录用户，我希望可以关闭当前、左侧、右侧、其他或全部可关闭 Tab，以便整理工作区。
10. 作为已登录用户，我希望关闭当前 Tab 后自动回到合理的相邻 Tab，以便不中断工作流。
11. 作为已登录用户，我接受切回 Tab 时按现有路由逻辑重新加载页面，以便第一阶段不改变业务组件生命周期。
12. 作为已登录用户，我希望通过面包屑看到首页、空间、项目、功能和资源层级，以便理解当前上下文。
13. 作为键盘用户，我希望使用快捷键打开功能搜索，以便减少鼠标导航成本。
14. 作为已登录用户，我希望搜索已有控制台功能并直接打开，以便快速进入低频功能。
15. 作为已登录用户，我希望搜索结果遵守现有权限，以便看不到无权访问的入口。
16. 作为已登录用户，我希望通过顶部快捷入口进入当前空间项目列表、当前项目文档等高频页面，以便减少导航层级。
17. 作为管理员，我希望管理员入口仅在具备对应权限时出现，以便保持现有权限边界。
18. 作为普通成员，我希望改版后原有业务按钮、表单、弹窗和接口行为保持不变，以便无须重新学习业务流程。
19. 作为文档维护者，我希望改版后公开浏览、分享和聚合页面保持原状，以便第一阶段不影响外部访问者。
20. 作为窄屏设备用户，我希望导航在空间不足时能够收敛或折叠，以便仍可访问核心功能。
21. 作为维护者，我希望视觉规范集中管理，以便后续业务页面逐步复用而非继续硬编码。
22. 作为维护者，我希望每个迁移切片都可以独立构建和验收，以便控制回归范围。
23. 作为维护者，我希望上游 Torna 版本仍可通过独立远端同步，以便持续获得安全修复和功能更新。
24. 作为维护者，我希望第一阶段不新增服务端接口、数据库结构和搜索索引，以便保持发布风险可控。

## Implementation Decisions

- 运行环境继续使用 Node 12，兼容上限为 Node 14；不升级 Vue、Vue Router、Vuex、Element UI、Vue CLI、Webpack、Sass 工具链和既有核心依赖。
- 新增一个统一控制台外壳作为深模块，对外只接收导航上下文、侧栏内容和业务内容插槽；顶部导航、工作区层级和响应式行为由外壳内部负责。
- 先在首页形成可运行样板，再迁移空间、项目、用户中心和管理员布局，避免一次性替换所有布局。
- 公开浏览、分享和聚合页面继续使用现有独立布局及现有文档 Tab，不与登录后控制台 Tab 合并。
- 登录后工作 Tab 以规范化路由为唯一身份，至少包含路由名称、路径参数和必要查询参数；同一身份重复访问时复用已有 Tab。
- 首页 Tab 固定且不可关闭。其他 Tab 支持关闭当前、关闭左侧、关闭右侧、关闭其他和关闭全部可关闭项。
- 第一阶段不使用 `keep-alive`，不同时挂载多个业务页面。Tab 切换继续使用 Vue Router，业务页面生命周期与当前路由跳转保持一致。
- Tab 状态只保存在当前浏览器会话内存中。第一阶段不实现刷新恢复、跨窗口同步和服务端同步。
- 功能搜索基于前端导航命令注册表，注册表包含标题、关键词、目标路由、上下文要求和权限要求；不调用新增后端接口。
- 搜索结果只展示当前用户有权访问且上下文完整的命令。缺少空间或项目上下文的命令不生成无效链接。
- 快捷操作只执行现有路由导航，不直接调用业务子组件方法，不跨页面打开创建、导入、同步或发布弹窗。
- 面包屑优先来自路由元数据和当前空间、项目状态。资源标题只能复用当前已有状态，不额外请求后端。
- 保留现有权限工具和路由结构，不在 UI 层复制一套权限模型。
- 视觉变量集中维护，覆盖品牌主色、中性色、语义色、字号、行高、间距、圆角、阴影、边框、顶部栏高度、侧栏宽度和 Tab 高度。
- 视觉风格采用浅色、紧凑、高信息密度的开发者控制台方案；不照搬特定云厂商，不引入其品牌资产。
- 新组件避免使用 `any` 式不透明数据约定、魔法数字和直接修改 Vuex 状态；状态变更通过明确的 mutation/action 完成。
- 现有业务页面的行内样式和历史样式问题只在影响外壳布局时做最小修正，全面业务页面样式治理留到后续阶段。

## Testing Decisions

- 测试外部可观察行为，不测试组件内部实现细节或具体 class 拼接过程。
- 为路由 Tab 状态模块补充单元测试，覆盖新增、复用、激活、关闭、相邻回退、固定首页和权限切换后的清理行为。
- 为功能搜索的纯函数或注册表过滤模块补充单元测试，覆盖关键词匹配、权限过滤、上下文过滤和结果路由生成。
- 为控制台外壳关键组件补充浅层组件测试，覆盖顶部区域、侧栏插槽、Tab 区域和窄屏状态的可见行为。
- 面包屑继续参考现有 Breadcrumb 组件测试方式，扩展空间、项目和无标题路由等场景。
- 每个切片至少执行 ESLint、相关 Jest 单元测试和生产构建。由于依赖较老，安装和构建必须在 Node 12 环境中执行。
- 手工验证覆盖首页、空间、项目、用户中心、管理员页面的路由跳转，以及普通成员和管理员两类权限视图。
- 手工验证浏览器宽度至少覆盖桌面宽屏、常规笔记本宽度和窄屏收敛状态。
- 第一阶段不新增端到端测试框架，避免为 UI 改造扩大工具链；必要的跨页行为使用现有测试栈和手工验收覆盖。

## Out of Scope

- 任何后端 Java 代码、接口契约、数据库结构、搜索索引和权限模型改动。
- Vue 3、Vite、新版 Element Plus 或其他前端框架迁移。
- Node 版本升级以及依赖包的全量升级或安全重整。
- 跨空间、跨项目的文档全文检索。
- 页面实例缓存、未保存表单保护、Tab 刷新恢复和多窗口状态同步。
- 从顶部快捷入口直接创建空间、项目、应用、文档，或直接触发导入、同步、发布操作。
- 公开文档浏览、分享、聚合页面的布局和视觉改造。
- 空间管理、项目管理、文档编辑、成员管理、常量管理、发布管理等业务页面内部的全面重构。
- 移动端专用交互设计；第一阶段只保证窄屏下核心功能可访问。
- 深色主题、品牌换肤和用户自定义布局。

## Further Notes

- 当前代码已经存在公开文档端 Tab，但其允许路由、标题来源和布局计算与登录后控制台目标不同，不应直接扩展为共享状态；可以复用交互经验，但必须隔离状态域。
- 当前多套登录态布局结构高度相似，统一外壳能够减少重复，但迁移时必须保留各布局的数据初始化逻辑和权限判断。
- 第一阶段完成后，再按业务价值逐步优化项目文档列表、文档查看、编辑页和管理表格等内部页面。
- 改造仓库以 GitHub `origin` 管理，上游 Torna 以 Gitee `upstream` 保留，第一阶段基线为 `v1.35.9`。
