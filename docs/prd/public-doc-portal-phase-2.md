# Torna 公开文档门户 UI 优化第二阶段 PRD

## Problem Statement

Torna 的 `/share` 与 `/show` 承担匿名文档分享和聚合文档展示，但当前页面仍然沿用内部工具式布局：顶部只有折叠和语言入口，左侧是基础树形目录，中间直接展示文档，访问过的文档持续堆积为 Tab。页面缺少明确的品牌、项目上下文、门户首页、内容层级和阅读导航，因此外部访问者看到的是一个粗糙的后台文档页面，而不是可信、现代、易阅读的开发者文档门户。

两个入口还存在体验不一致：`/share/:id` 会自动打开第一篇文档，`/show/:id` 在未选择文档时基本为空白；分享模式和聚合模式分别维护高度重复的布局、导航和响应式逻辑。继续分别修改会扩大重复代码和后续维护成本。

第二阶段必须继续兼容 Node 12、Vue 2、Vue Router 3、Vuex 3、Element UI 2 和 Vue CLI 3，不升级框架或核心依赖，不修改 Java 后端、接口契约、权限规则、密码校验和文档数据结构。

## Solution

为 `/share` 与 `/show` 建立统一的公开文档门户体验，同时保留两种模式各自的数据接口和访问规则：

- 使用统一的公开门户外壳承载品牌顶部栏、左侧文档导航、正文工作区和响应式行为。
- 根地址不再自动打开第一篇文档，而是展示门户首页。
- 门户首页使用现有名称、描述或备注以及文档目录数据，展示品牌介绍、文档搜索、分类卡片和快速开始入口。
- 文档详情改为单文档阅读模式，移除公开端多文档 Tab；通过左侧目录、门户搜索和浏览器历史导航。
- 桌面端采用“左侧文档目录 + 中间正文 + 右侧页内目录”的三栏结构。
- 右侧页内目录完全由前端生成，支持 HTTP、Dubbo、自定义富文本和 Markdown 文档；窄屏下自动收敛。
- 统一密码访问、禁用、无数据、加载和异常状态的门户视觉，但不改变现有校验接口和存储逻辑。
- 公开端使用第一阶段已确定的“文档协作站”品牌资产和视觉变量，并采用比管理控制台更宽松的阅读密度。

## User Stories

1. 作为匿名访问者，我希望分享链接打开后先看到清晰的门户首页，以便理解当前文档集合的用途。
2. 作为匿名访问者，我希望聚合项目根地址不再出现空白内容，以便知道下一步可以访问什么。
3. 作为匿名访问者，我希望页面顶部展示统一品牌和当前文档集合名称，以便确认访问来源。
4. 作为匿名访问者，我希望聚合项目展示已有项目描述，以便理解项目背景。
5. 作为匿名访问者，我希望分享配置可以展示已有分享名称和备注，以便获得必要说明。
6. 作为匿名访问者，我希望在门户首页搜索当前文档集合，以便快速定位接口或章节。
7. 作为匿名访问者，我希望门户首页按现有目录层级生成分类卡片，以便快速浏览内容范围。
8. 作为匿名访问者，我希望分类卡片只使用已有数据，以便不依赖新增后端配置。
9. 作为匿名访问者，我希望点击文档卡片或搜索结果后进入对应详情，以便开始阅读。
10. 作为匿名访问者，我希望随时通过品牌或首页入口返回门户首页，以便重新选择内容。
11. 作为匿名访问者，我希望左侧目录始终表达当前文档集合的层级，以便了解所在位置。
12. 作为匿名访问者，我希望左侧目录支持名称、URL 和请求方法搜索，以便定位接口。
13. 作为匿名访问者，我希望当前文档在目录中具有明确选中态，以便确认当前位置。
14. 作为匿名访问者，我希望目录展开、折叠和滚动状态稳定，以便浏览大型文档集合。
15. 作为匿名访问者，我希望文档详情只显示当前文档，不累积多文档 Tab，以便专注阅读。
16. 作为匿名访问者，我希望使用浏览器前进和后退切换文档，以便符合标准网页导航习惯。
17. 作为匿名访问者，我希望 HTTP 文档突出方法、URL、状态和维护人，以便快速扫描接口信息。
18. 作为匿名访问者，我希望请求参数、响应参数和示例具有清晰卡片与标题层级，以便阅读复杂接口。
19. 作为匿名访问者，我希望代码示例保持可复制，以便直接用于调试。
20. 作为匿名访问者，我希望 HTTP 文档右侧提供页内目录，以便快速跳转到请求或响应章节。
21. 作为匿名访问者，我希望 Dubbo 文档也使用一致的阅读布局和页内目录，以便降低学习成本。
22. 作为匿名访问者，我希望 Markdown 和自定义文档可以根据正文标题生成页内目录，以便阅读长文档。
23. 作为匿名访问者，我希望滚动正文时右侧目录同步高亮当前章节，以便知道阅读位置。
24. 作为匿名访问者，我希望点击页内目录后平滑滚动，以便保持上下文。
25. 作为匿名访问者，我希望调试入口仍由现有分享或聚合设置控制，以便权限行为不变。
26. 作为匿名访问者，我希望语言切换功能继续可用，以便阅读不同语言界面。
27. 作为访问加密分享的用户，我希望看到现代、明确的密码访问页面，以便理解当前需要验证。
28. 作为访问加密分享的用户，我希望密码验证继续使用现有接口和本地授权记录，以便行为保持兼容。
29. 作为访问已禁用项目的用户，我希望看到明确的不可访问状态，而不是裸文本或空白页面。
30. 作为访问空文档集合的用户，我希望看到友好的空状态，以便知道不是页面加载失败。
31. 作为网络异常用户，我希望看到明确的加载或错误反馈，以便区分等待、无数据和不可访问。
32. 作为窄屏设备用户，我希望左侧目录可以抽屉式打开，右侧页内目录自动隐藏，以便正文仍然可读。
33. 作为键盘用户，我希望主要导航、搜索结果和目录具有可见焦点，以便不用鼠标完成访问。
34. 作为维护者，我希望 `/share` 与 `/show` 共用门户外壳和纯展示组件，以便减少重复维护。
35. 作为维护者，我希望两种模式保留独立的数据适配层，以便不强行统一不同接口结构。
36. 作为维护者，我希望门户组件通过明确的展示模型接收数据，以便测试不依赖真实后端。
37. 作为维护者，我希望 `/view` 保持现状，以便第二阶段不扩大登录态预览回归范围。
38. 作为维护者，我希望每个改造切片都能独立构建和验收，以便控制发布风险。
39. 作为维护者，我希望所有新增样式使用集中变量，以便后续持续调整品牌视觉。
40. 作为维护者，我希望生产构建继续使用 Node 12 至 Node 14，以便兼容现有工具链。

## Implementation Decisions

- 第二阶段只覆盖匿名访问的分享模式和聚合模式，登录态预览入口保持现状。
- 新建统一公开门户外壳作为深模块，对外接收门户元数据、导航区域、正文区域和响应式状态，不负责调用具体业务接口。
- 分享模式和聚合模式继续在各自布局层调用原有接口，并将结果转换为统一的前端门户展示模型。
- 展示模型至少包含门户标识、标题、说明、文档树、当前文档和访问模式；不复制后端权限模型。
- 根路由展示门户首页，只有携带文档标识的子路由才展示文档详情。
- 分享模式不再自动跳转第一篇文档；聚合模式不再保留空白根页面。
- 门户首页基于现有目录数据生成分类和快速入口，不新增门户配置表、轮播图、推荐位或后端管理能力。
- 公开门户不挂载现有多文档 Tab。登录态预览继续保留原 Tab 行为和状态域。
- 左侧目录继续支持两种模式已有的数据结构差异，通过模式适配函数转换为统一、只读的导航节点。
- 文档详情由阅读容器统一控制正文最大宽度、页内目录、滚动区域和窄屏收敛；现有文档展示组件继续负责具体业务内容。
- HTTP 和 Dubbo 文档使用稳定章节标识生成页内目录；Markdown 和自定义富文本在渲染后提取标题，不请求后端生成大纲。
- 页内目录滚动监听封装为独立、可清理的前端模块，避免在多个页面重复绑定全局事件。
- 公开端调试、复制、语言切换、密码验证和文档详情请求继续调用现有接口，不修改请求参数或响应结构。
- 加密分享仍使用现有摘要算法、校验接口和本地授权键；只重构视觉、错误提示和响应式布局。
- 统一处理加载中、空目录、禁用、无权限或不存在状态，避免使用裸文本和空白页面。
- 视觉风格使用浅色、清晰、内容优先的开发者门户方案；品牌色复用第一阶段视觉变量，但正文采用更宽松的行高和间距。
- 桌面端目标布局为固定顶部栏、可收敛左侧目录、有限宽度正文和右侧粘性页内目录；窄屏隐藏右侧目录并将左侧目录变为抽屉。
- 不引入新的 UI 框架、Markdown 引擎、状态管理库、全文搜索库或端到端测试框架。
- 不为复用而强行合并分享和聚合接口请求；只提取稳定的展示层能力。

## Testing Decisions

- 测试用户可观察行为，不断言内部方法名、具体 class 拼接或实现细节。
- 为统一门户外壳补充组件测试，覆盖品牌、顶部栏、侧栏、正文、窄屏遮罩和折叠事件。
- 为文档树适配与门户搜索补充纯函数测试，覆盖分享和聚合两种数据、文件夹、文档、空数据和关键词匹配。
- 为门户首页补充组件测试，覆盖标题、说明、分类卡片、空状态和文档跳转事件。
- 为页内目录模块补充测试，覆盖章节生成、点击跳转、活动章节更新和事件清理。
- 为密码和禁用状态补充组件测试，确保不改变提交、校验和授权行为。
- 参考第一阶段控制台外壳、导航纯函数和组件测试的现有 Jest/Vue Test Utils 写法。
- 每个切片执行新增或修改文件的定向 ESLint、相关 Jest 测试和生产构建。
- 人工验证至少覆盖公开分享、加密分享、聚合项目、HTTP 文档、Dubbo 文档、Markdown/自定义文档、空目录和禁用项目。
- 人工视觉验证覆盖 1440px、1024px 和窄屏状态，并确认键盘焦点、滚动、目录高亮和浏览器历史导航。
- 回归验证 `/view` 仍保留原布局和多文档 Tab，避免公共组件修改造成登录态预览回归。

## Out of Scope

- 任何 Java 后端、数据库、接口契约、权限模型和密码规则修改。
- 登录态管理控制台和 `/view` 预览页面的第二轮视觉改造。
- Vue 3、Vite、Element Plus、Node 升级和核心依赖升级。
- 跨项目或跨分享链接的全文搜索。
- 搜索索引、搜索联想、搜索历史和服务端搜索排行。
- 门户内容运营后台、轮播图、公告、推荐位、版本选择和自定义主题管理。
- 用户评论、反馈、评分、登录注册和开发者账号中心。
- 自动生成 SDK、在线代码沙箱和新增在线调试能力。
- 修改现有文档编辑、发布、分享配置和聚合配置流程。
- 深色主题和用户自定义布局。
- 将 `/share` 与 `/show` 的业务接口合并为新接口。

## Further Notes

- 分享接口当前提供分享名称和备注，聚合项目接口提供项目名称和描述，足以构建第一版门户首页；两种模式内容丰富度不同，展示层必须允许说明为空。
- 分享目录与聚合目录字段不同，统一导航应使用显式适配函数，不应在组件模板中散落模式判断。
- 现有 HTTP、Dubbo 和自定义文档组件包含大量业务行为。第二阶段应通过门户模式、稳定章节标识和外层阅读容器渐进增强，避免复制整套文档渲染实现。
- 当前工作区还有独立的 Markdown 对比修复和构建产物归档文件。第二阶段改造不得覆盖、删除或混入这些既有改动。
